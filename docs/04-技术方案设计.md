
## 3. 技术选型

### 3.1 前端

- Vue 3；
- TypeScript；
- Vite；
- Element Plus；
- Pinia；
- 原因：与用户已有 Vue/TypeScript 基础匹配，组件库可以减少表单、表格、上传和状态反馈的开发量。
- Pinia 用于保存跨页面状态，例如登录用户、Token、当前知识库和全局请求状态；页面内部的临时输入仍使用组件自身状态，不为了所有变量都放入 Pinia。
- HTML、JavaScript 和 CSS 会作为 Vue 页面开发的基础技术使用，但不单独把它们当作额外框架堆叠。

### 3.2 后端

- Python 3.13；
- FastAPI；
- Uvicorn；
- Pydantic；
- SQLAlchemy 2；
- Alembic；
- 原因：用户已经学习过 FastAPI、依赖注入、SQLAlchemy、JWT、文件上传和 SSE；SQLAlchemy 与 Alembic 负责业务数据和数据库迁移。

### 3.3 关系型数据库

- MySQL 8.0.41；
- 主机：`127.0.0.1`；
- 端口：`3306`；
- 用户：`root`；
- 数据库名：建议使用 `dev_atlas`，初始化前再确认是否创建；
- 原因：用户已经使用过 MySQL，适合保存用户、知识库、文档、版本、分析记录等结构化数据。

### 3.4 向量存储

- Chroma Persistent Client；
- 原因：本地开发简单，用户已经学习过 Chroma 的集合、metadata、query 和持久化；不需要额外启动 Milvus 服务。
- 向量库只负责语义检索，不替代 MySQL 保存业务事实。

### 3.5 Embedding

- 本地模型：`BAAI/bge-small-zh-v1.5`；
- 原因：中文效果适合当前资料，模型已经下载过，无云端 Embedding 费用和额外 API 依赖；当前 MVP 文档量不大，体量足够。
- 暂不更换更大模型，也不加入 Reranker。只有固定测试集证明召回不足时，才评估升级。

### 3.6 LLM

- 提供商：DeepSeek；
- 目标模型：`deepseek-v4-flash`；
- 通过 DeepSeek 的 OpenAI 兼容接口调用；
- 代码层采用独立的 LLM Service，不把调用细节散落在路由和 RAG 代码中；
- 原因：用户已经调通 DeepSeek API，直接 HTTP/SDK 调用更容易理解和排错；当前不引入 LangChain 作为核心依赖。
- 正式开发前必须先用最小请求验证模型 ID、Base URL、鉴权、普通响应和流式响应；如果服务端返回模型不可用，优先以 DeepSeek 当前 API 文档和实际错误为准。

### 3.7 认证

- JWT Bearer Token；
- 密码哈希；
- FastAPI Dependency 获取当前用户；
- 原因：用户已经掌握 JWT 流程，适合 MVP 的无状态接口认证。

### 3.8 流式传输

- SSE；
- FastAPI `StreamingResponse`；
- `text/event-stream`；
- 事件类型：`token`、`citation`、`done`、`error`；
- 原因：问答和故障分析需要边生成边展示，浏览器端可以持续接收服务端事件。

### 3.9 Redis

- 不作为第一条主链路的强依赖；
- 主链路稳定后，可以用于登录失败限流或短期问答缓存；
- 只有真实实现、测试并记录用途后，才写入简历技术栈；
- 不为了凑技术栈加入 Redis 集群、持久化和分布式锁。

### 3.10 部署

- 当前：本机分别启动 MySQL、FastAPI 和 Vue 开发服务器；
- 后续：如果安装 Docker，再使用 Docker Compose 做可复现部署；
- Docker 不作为阶段 4-8 的阻塞条件。

### 3.11 Git 和 GitHub

- 正式开发开始时初始化本地 Git；
- 完成一个可运行、可验证的功能后提交一次，例如“完成认证接口”“完成文档上传”“完成 RAG 检索”；
- 不要求每创建一个文件就提交，也不把未验证的大段代码一次性提交；
- 第一版主分支保持可运行，功能开发可以使用简短的 feature 分支；
- 本地项目结构稳定、首个基础版本可运行后，再创建 GitHub 私有或公开仓库并推送；
- 推送前检查 `.gitignore`，确保 `.env`、API Key、数据库密码、上传文件、Chroma 数据和本地缓存不进入远程仓库。

## 4. 系统架构

```text
浏览器
  │ HTTP / SSE
  ▼
Vue 3 + TypeScript + Element Plus
  │ REST API / SSE
  ▼
FastAPI 模块化单体
  ├── routers       HTTP 路由和依赖注入
  ├── schemas       请求/响应数据校验
  ├── services      业务流程编排
  ├── repositories  MySQL 数据访问
  ├── core          JWT、文件解析、切分、Embedding、检索、Prompt
  └── integrations  DeepSeek、Chroma、文件存储
       ├── MySQL 8.0.41：用户、知识库、文档、版本、记录
       ├── 文件系统：原始上传文件
       ├── Chroma：文档块向量和检索 metadata
       └── DeepSeek：答案和故障分析生成
```

采用模块化单体而不是微服务：

- 本地部署简单；
- 调试路径短；
- 适合第一个完整项目；
- 模块边界清晰，后续仍可拆分；
- 不需要为了架构形式增加网络、部署和运维成本。

## 5. 后端模块职责

### routers

负责 URL、HTTP 方法、鉴权依赖、请求接收和响应返回，不写复杂业务逻辑。

### schemas

负责请求参数和响应结构，例如注册请求、上传响应、问答请求和 SSE 事件数据。

### services

负责业务流程，例如创建知识库、文档入库、问答、故障分析和状态变更。

### repositories

负责 MySQL 查询和写入，避免把 SQL 细节散落在路由和业务流程中。

### core

负责可复用的技术能力：JWT、密码哈希、文件解析、文本切分、Embedding、向量检索和 Prompt 构造。

### integrations

负责外部依赖适配：DeepSeek 客户端、Chroma 客户端和文件存储。

## 6. RAG 技术流程

### 6.1 入库

```text
文件上传
  → 计算 SHA-256
  → MySQL 创建文档版本（pending）
  → 解析 TXT/Markdown/PDF
  → 按规则切分文本
  → BGE 生成向量
  → Chroma upsert 文档块、向量和 metadata
  → MySQL 更新 indexed
```

metadata 至少包含：

- `knowledge_base_id`；
- `document_id`；
- `document_version_id`；
- `chunk_index`；
- `source_filename`；
- `version_number`；
- `owner_id`；
- `status` 或可检索标记。

### 6.2 查询

```text
用户问题
  → 权限校验
  → BGE 生成问题向量
  → Chroma 按 knowledge_base_id 和 indexed 条件检索
  → 读取文档块和来源 metadata
  → 拼接受控 Prompt
  → DeepSeek 生成
  → SSE 返回 token 和 citation
```

数据库和向量库的分工：

- MySQL 是业务事实来源；
- Chroma 是语义检索索引；
- MySQL 记录的版本状态决定哪些向量允许被检索；
- 删除或替换文档时，必须同步删除旧向量。

## 7. 权限方案

### 7.1 认证

登录成功后签发 JWT。后续请求通过 `Authorization: Bearer <token>` 携带 Token，后端解析 Token 得到当前用户。

### 7.2 业务权限

知识库表保存 `owner_id`。访问知识库、文档、问答和故障分析时：

1. 先通过 JWT 得到当前用户；
2. 查询知识库时同时检查 `knowledge_base_id` 和 `owner_id`；
3. 向量检索时加入 `knowledge_base_id` 过滤；
4. 不能只依赖前端隐藏按钮。

### 7.3 越权处理

- 未登录：`401 Unauthorized`；
- 已登录但无权限：统一返回 `403 Forbidden` 或按资源不存在策略返回 `404`，具体在 API 文档阶段统一；
- 不把其他用户的资源名称、文档内容或向量 metadata 返回给客户端。

## 8. 异常处理方案

### 输入类错误

- 空标题/空日志：`400` 或 Pydantic `422`；
- 不支持的文件：`415`；
- 文件过大：`413`；
- 无效 Token：`401`。

### 业务类错误

- 知识库不存在：`404`；
- 无权限：`403`；
- 重复文件：返回明确的重复状态，不创建重复数据；
- 文档索引失败：数据库记录 `failed` 和错误原因。

### 外部服务错误

- DeepSeek 超时或失败：后端转换为统一错误响应，SSE 发送 `error` 事件；
- Chroma 写入失败：文档保持 `failed`，清理已写入的临时向量；
- Embedding 失败：不标记为 `indexed`；
- 数据库提交失败：回滚事务并保留可排查日志。
