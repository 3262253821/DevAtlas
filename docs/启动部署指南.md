# DevAtlas 启动部署指南

本指南面向 **Windows + PowerShell** 的本地开发环境，带你从零把 DevAtlas 跑起来。

> **重要说明**：DevAtlas 目前是**开发环境 / MVP**项目，本文只描述本地开发环境的启动方式，
> **不包含任何生产环境部署方案**（没有 Docker、没有反向代理、没有进程守护、没有 HTTPS）。
> 文中的密钥一律使用占位符，请勿把真实密码或 API Key 写进任何提交到仓库的文件。

## 一、环境要求

| 依赖 | 版本要求 | 检查命令 |
| --- | --- | --- |
| Python | 3.13 | `python --version` |
| Node.js | 20 及以上 | `node --version` |
| npm | 随 Node.js 安装 | `npm --version` |
| MySQL | 8.x | `mysql --version` |

```powershell
python --version
node --version
npm --version
mysql --version
```

内存建议 8 GB 以上（首次加载 Embedding 模型占用较多），磁盘建议预留 2 GB
（模型缓存、上传文件和 Chroma 数据）。

## 二、创建 MySQL 数据库

登录 MySQL 并创建数据库：

```powershell
mysql -u root -p
```

```sql
CREATE DATABASE dev_atlas
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

验证：

```sql
SHOW DATABASES LIKE 'dev_atlas';
```

数据库表结构**不要手工创建**，统一由 Alembic 迁移生成。

## 三、配置 .env

在项目根目录从模板复制：

```powershell
Set-Location E:\RagKnowledgeSystem
Copy-Item .env.example .env
```

然后编辑 `.env`，把占位符替换成本机真实值：

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| `APP_ENV` | 运行环境，种子脚本会拒绝 `production` | `development` |
| `APP_HOST` | 后端监听地址 | `127.0.0.1` |
| `APP_PORT` | 后端端口 | `8000` |
| `DATABASE_URL` | SQLAlchemy 连接串（PyMySQL 驱动） | `mysql+pymysql://root:<你的密码>@127.0.0.1:3306/dev_atlas` |
| `JWT_SECRET_KEY` | JWT 签名密钥，需足够长且随机 | `<自行生成的长随机字符串>` |
| `DEEPSEEK_API_KEY` | DeepSeek API Key | `<你的 API Key>` |
| `DEEPSEEK_BASE_URL` | DeepSeek 接口地址 | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 使用的模型名 | `deepseek-v4-flash` |
| `CHROMA_PERSIST_DIR` | 向量库持久化目录（相对项目根） | `others/chroma` |
| `UPLOAD_DIR` | 上传文件目录（相对项目根） | `others/uploads` |
| `EMBEDDING_MODEL` | Embedding 模型名 | `BAAI/bge-small-zh-v1.5` |

注意：

- `.env` 已被 `.gitignore` 忽略，**不要提交**，仓库里只保留 `.env.example`；
- 配置由 `backend/app/core/config.py` 的 `Settings` 读取，`env_file` 指向项目根目录的
  `.env`，`extra="ignore"` 表示 `.env` 里多写的无关变量不会导致启动失败；
- `DEEPSEEK_MODEL` 请以 DeepSeek 官方当前可用的模型名为准，配置错误会在问答时返回 `502`。

## 四、安装后端依赖

```powershell
Set-Location E:\RagKnowledgeSystem
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
```

如果 PowerShell 阻止执行激活脚本，可只对当前会话放开：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

依赖里包含 `sentence-transformers` 与 `chromadb`，安装体积较大，请耐心等待。

## 五、执行数据库迁移

在项目根目录执行（`alembic.ini` 位于根目录）：

```powershell
alembic upgrade head
```

查看当前已应用的迁移版本：

```powershell
alembic current
```

如果需要回退一个版本：

```powershell
alembic downgrade -1
```

数据库结构变更必须通过 Alembic，不要手工改表。

## 六、启动后端

在项目根目录执行：

```powershell
python -m uvicorn app.main:app --reload --app-dir backend --host 127.0.0.1 --port 8000
```

参数说明：`--app-dir backend` 让 uvicorn 找到 `backend/app` 包；`--reload` 仅用于开发，
代码变更后自动重启。

### 验证后端起没起来

先看服务本身是否存活：

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health"
```

再看数据库是否连通（这一步能区分「服务起来了但连不上库」）：

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health/db"
```

打开 Swagger 交互式文档，确认路由已加载：

```text
http://127.0.0.1:8000/docs
```

## 七、安装并启动前端

新开一个 PowerShell 窗口：

```powershell
Set-Location E:\RagKnowledgeSystem\frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

前端地址：

```text
http://127.0.0.1:5173
```

前端通过 `frontend/.env.local` 中的 `VITE_API_BASE_URL` 访问后端，默认指向
`http://127.0.0.1:8000`。该文件只保存本地地址，不提交到 Git。

如果需要显式指定后端地址，创建 `frontend/.env.local`：

```text
VITE_API_BASE_URL=http://127.0.0.1:8000
```

### 端口约定

| 服务 | 端口 | 地址 |
| --- | --- | --- |
| 后端 FastAPI | 8000 | http://127.0.0.1:8000 |
| Swagger | 8000 | http://127.0.0.1:8000/docs |
| 前端 Vite | 5173 | http://127.0.0.1:5173 |
| MySQL | 3306 | 127.0.0.1:3306 |

## 八、CORS 注意事项

`backend/app/main.py` 中的 CORS 白名单**只包含两个来源**：

```python
allow_origins=[
    "http://127.0.0.1:5173",
    "http://localhost:5173",
]
```

因此：

- 如果前端换到别的端口（例如 `5174`），浏览器会拦截请求，必须同步把新来源加入白名单；
- `allow_credentials=True`，所以**不能**把 `allow_origins` 写成 `["*"]`；
- 修改白名单后需要重启后端才生效（`--reload` 通常会自动重启）。

## 九、恢复开发种子数据

如果本地测试把账号、知识库或文档删掉了，可以执行种子脚本恢复：

```powershell
python backend/scripts/seed_dev_data.py
```

脚本行为：

- 幂等创建开发账号（默认 `devatlas-demo`），**不会覆盖已有账号的密码**，
  只会把 `is_active` 补成 `True`；
- 幂等创建开发知识库（默认 `DevAtlas 开发演示知识库`）；
- 导入 `tests` 目录下的三个示例文档：`DevAtlas团队入门手册.txt`、
  `订单服务故障排查手册.md`、`DevAtlas系统架构与操作规范.pdf`；
- 通过 SHA-256 判断内容是否已存在：已存在且 `indexed` 就跳过；已存在但 `failed`
  会调用重新索引；不存在才复制文件并执行导入；
- 当 `APP_ENV` 为 `production` 或 `prod` 时**直接拒绝执行**。

可用参数：

```powershell
python backend/scripts/seed_dev_data.py `
  --username devatlas-demo `
  --password "<你的本地开发密码>" `
  --knowledge-base-name "DevAtlas 开发演示知识库"
```

只想建账号和知识库、不导入文档时加 `--skip-documents`。也可以用环境变量
`DEVATLAS_SEED_USERNAME`、`DEVATLAS_SEED_PASSWORD`、`DEVATLAS_SEED_KB_NAME` 传入。

> 默认账号 `devatlas-demo` / `DevAtlas123!` **仅用于本地开发**，
> 不要用于任何真实环境，也不要把真实密码写进脚本或提交到 Git。

执行前请确认迁移已完成（`alembic upgrade head`）。

## 十、启动后验证顺序

建议按下面的顺序逐步自检，出问题时能立刻定位是哪一层：

1. `python --version` / `node --version` / `mysql --version` 版本符合要求；
2. `alembic current` 显示已到最新迁移版本；
3. `GET /health` 返回成功；
4. `GET /health/db` 返回成功（失败多为数据库连接问题）；
5. 打开 `/docs` 能看到 auth、knowledge-bases、documents、retrieval、qa、incidents 路由；
6. 前端 `http://127.0.0.1:5173` 能打开登录页；
7. 注册一个新账号，或执行种子脚本后登录；
8. 创建一个知识库；
9. 上传一个 `.md` 或 `.txt` 文档，确认状态变成 `indexed`；
10. 在问答页提问，确认能收到流式回答并显示引用来源；
11. 发起一次故障分析，确认 `/incidents` 能看到历史记录；
12. 重复上传同一个文件，确认返回 `duplicate=true` 且没有产生新版本。

## 十一、跑测试与构建

```powershell
# 后端编译检查
python -m compileall -q backend/app backend/scripts

# 后端自动化测试
python -m pytest tests -q

# 前端类型检查 + 构建
Set-Location frontend
npm run build
```

当前真实结果：`compileall` 退出码 0；`pytest` 为 `23 passed, 2 warnings`；
`npm run build` 成功（会有 chunk 超过 500 kB 的提示）。

## 十二、常见启动错误

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 启动即报数据库连接失败 | MySQL 未启动，或 `DATABASE_URL` 用户名/密码/端口错误 | 启动 MySQL 服务，核对 `.env` 中的连接串 |
| `Unknown database 'dev_atlas'` | 数据库未创建 | 执行第二节的 `CREATE DATABASE dev_atlas` |
| `GET /health` 正常但 `/health/db` 失败 | 服务起来了但连不上库 | 检查 `DATABASE_URL` 与 MySQL 服务状态 |
| 表不存在 / `Table 'dev_atlas.users' doesn't exist` | 没有执行迁移 | `alembic upgrade head` |
| `alembic` 命令找不到 | 虚拟环境未激活 | 激活 `.venv` 后重试，或用 `python -m alembic upgrade head` |
| 端口 8000 被占用 | 已有 uvicorn 进程在跑 | 结束旧进程，或换端口（记得同步前端配置） |
| 端口 5173 被占用 | 已有 Vite 进程在跑 | 结束旧进程，或换端口（记得同步 CORS 白名单） |
| 浏览器报 CORS 错误 | 前端端口不在白名单内 | 把新来源加入 `backend/app/main.py` 的 `allow_origins` |
| 问答返回 `502` | 缺少 `DEEPSEEK_API_KEY`、网络不通或模型名错误 | 检查 `.env` 的 Key、网络和 `DEEPSEEK_MODEL` |
| 问答返回 `503` | 检索失败（Embedding 或 Chroma 异常） | 查看后端日志，确认 `others/chroma` 目录可写 |
| 第一次启动很慢 | 首次下载并加载 BGE 模型 | 等待完成，之后使用本地缓存；确认网络可达 HuggingFace |
| 文档上传后一直是 `failed` | 解析失败，例如扫描版 PDF 无文本层 | 查详情接口的 `error_message`，或换成 `.md`/`.txt` |
| 检索总是没有结果 | 文档不是 `indexed` 状态 | 查看文档详情确认状态，必要时重新索引 |
| PowerShell 不允许激活虚拟环境 | 执行策略限制 | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| `npm install` 失败 | 网络或镜像问题 | 配置 npm 镜像后重试 |
| `npm run build` 报类型错误 | TypeScript 类型问题 | 按提示修复后重试，构建会先跑 `vue-tsc -b` |

## 十三、停止服务

在对应窗口按 `Ctrl + C` 即可停止 uvicorn 和 Vite。数据库数据、上传文件和 Chroma 数据
都持久化在本地，重启后仍然存在。
