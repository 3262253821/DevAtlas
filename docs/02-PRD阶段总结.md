## 本阶段产出

- `02-产品需求文档-PRD.md`

PRD 已明确：

- 产品定位、核心价值和用户痛点；
- 核心用户为值班/运维工程师，研发工程师为次要用户；
- MVP 采用知识库作为主要容器，不在首版单独实现项目/工作空间两层结构；
- 用户认证、文档上传、索引状态、文档版本、RAG 问答、引用来源、故障分析、SSE 和基础权限范围；
- P0、P1 和后续 P2 功能；
- 重复上传幂等、索引失败、旧向量清理、越权访问等验收要求；
- 故障分析记录转知识属于后续迭代，不属于当前 MVP 必做范围。

## 五项确认结果

1. MVP 以知识库为主要容器，不提前增加项目/工作空间两层结构；
2. 核心用户为值班/运维工程师，研发工程师为次要用户；
3. 索引状态、重复上传幂等、引用来源和旧向量清理纳入第一版验收；
4. 故障分析记录转知识放到后续迭代；
5. P0/P1 划分和页面范围接受。

## 不能丢失的产品决策

- 第一版不是自动修复生产系统，只提供有来源的 AI 辅助分析；
- 只有 `indexed` 状态的文档版本可以参与默认检索；
- 用户只能访问自己有权限的知识库；
- 数据库业务查询和向量检索都必须做权限过滤；
- 文档、版本、文档块和向量 ID 必须保留明确关联；
- 文档更新或删除后，旧向量不能继续被默认检索；
- P0 主链路优先于页面装饰和高级检索功能。
