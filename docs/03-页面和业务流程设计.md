# 阶段 3：页面和业务流程设计

## 文档状态

- 版本：v0.1（阶段 3 已确认）
- 项目：DevAtlas｜研发知识协同平台
- 前置文档：`01-项目立项和问题分析.md`、`02-产品需求文档-PRD.md`
- 当前状态：已由用户确认，未进入代码开发

## 1. 设计目标

本阶段只回答三个问题：

1. 用户从哪里进入系统，如何完成一次任务；
2. 每个页面展示什么、能做什么、有哪些状态；
3. 前端页面、后端接口、数据库和 RAG 流程如何衔接。

当前不确定的视觉细节，例如颜色、字体和最终布局，不阻塞后端开发；先冻结页面职责和业务流程。

## 2. 信息架构和导航

### 2.1 未登录区域

- `/login`：登录；
- `/register`：注册。

### 2.2 已登录区域

- `/workspaces`：知识库列表和创建入口；
- `/knowledge/:id`：知识库工作台；
- `/knowledge/:id/documents`：文档列表、上传和索引状态；
- `/knowledge/:id/qa`：知识库问答；
- `/knowledge/:id/incidents/new`：故障分析；
- `/incidents`：故障分析历史；
- `/profile`：当前用户信息和退出登录。

### 2.3 MVP 页面取舍

第一版把“知识库”作为主要工作容器，不单独增加项目和工作空间页面。`/workspaces` 是兼容已有命名的前端路径，但页面实际展示的是知识库列表；后续如果要引入团队工作空间，再扩展导航和数据模型。

## 3. 页面清单和职责

### 3.1 登录页（P0）

功能：输入用户名和密码，登录成功后进入知识库列表。

状态：

- 初始；
- 提交中；
- 登录失败；
- Token 保存失败；
- 登录成功跳转。

### 3.2 注册页（P0）

功能：创建用户账号。

状态：

- 初始；
- 参数校验失败；
- 用户名已存在；
- 提交中；
- 注册成功并跳转登录。

### 3.3 知识库列表页（P0）

功能：

- 查看当前用户的知识库；
- 创建知识库；
- 进入某个知识库；
- 删除知识库。

状态：

- 加载中；
- 空列表；
- 加载失败；
- 创建成功/失败；
- 删除确认/删除失败。

### 3.4 知识库工作台（P0）

功能：

- 展示知识库名称和摘要统计；
- 进入文档管理；
- 进入知识库问答；
- 进入故障分析；
- 展示最近文档和索引失败提示。

### 3.5 文档管理页（P0）

功能：

- 上传 Markdown、TXT、PDF；
- 查看文档名称、大小、版本、索引状态和失败原因；
- 查看文档详情；
- 删除文档；
- 失败文档重新索引。

状态：

- 文件选择；
- 上传中；
- `pending` 索引中；
- `indexed` 可检索；
- `failed` 显示失败原因；
- 不支持格式；
- 文件过大；
- 空列表。

### 3.6 知识库问答页（P0）

功能：

- 展示当前知识库；
- 输入问题；
- 提交问题；
- SSE 流式显示答案；
- 展示引用文档和来源片段；
- 中止生成；
- 重新提问。

状态：

- 无文档提示；
- 输入为空；
- 请求中；
- 流式接收中；
- 已完成；
- 无相关依据；
- LLM 失败；
- SSE 中断；
- 无权限。

### 3.7 故障分析页（P0）

功能：

- 输入故障标题；
- 粘贴错误日志或故障描述；
- 选择知识库；
- 开始分析；
- SSE 流式显示可能原因、排查步骤和参考资料；
- 生成完成后保存记录。

状态：

- 初始；
- 标题或日志为空；
- 提交中；
- 分析中；
- 分析完成；
- 分析失败；
- 用户主动中断；
- 无权限。

### 3.8 历史记录页（P1）

功能：

- 查看当前用户的故障分析记录；
- 查看标题、状态、创建时间和摘要；
- 进入详情；
- 删除自己的记录。

### 3.9 文档详情和版本页（P1）

功能：

- 查看文档元数据；
- 查看版本列表；
- 查看某个版本状态；
- 查看版本关联的来源片段。

## 4. 核心业务流程

### 4.1 注册和登录流程

```text
用户打开系统
  → 注册账号（首次使用）
  → 提交用户名和密码
  → 后端校验并保存密码哈希
  → 注册成功
  → 登录
  → 后端验证密码
  → 签发 JWT
  → 前端保存 Token
  → 请求携带 Authorization: Bearer <token>
```

失败路径：

- 用户名重复：注册失败，不创建用户；
- 参数不合法：返回参数错误；
- 密码错误：登录失败；
- Token 失效：跳转登录页，不能访问受保护数据。

### 4.2 创建知识库流程

```text
进入知识库列表
  → 点击创建
  → 填写名称和描述
  → 前端校验
  → 后端校验当前用户
  → 写入知识库记录和 owner_id
  → 返回知识库
  → 进入知识库工作台
```

### 4.3 文档上传和索引流程

```text
进入文档管理
  → 选择文件
  → 前端检查扩展名和大小
  → 上传到后端
  → 后端检查用户对知识库的权限
  → 计算文件哈希
  → 判断是否重复
  → 创建文档/新版本，状态 pending
  → 保存原始文件
  → 解析文本
  → 切分文本
  → 生成 Embedding
  → 写入 Chroma
  → 更新为 indexed
```

失败路径：

```text
任意处理步骤失败
  → 记录 failed 和错误原因
  → 清理本次产生的临时向量/文件
  → 页面允许重新索引
```

关键规则：

- 只有 `indexed` 版本参与默认检索；
- 同一知识库内相同文件哈希不重复创建数据；
- 内容变化时创建新版本；
- 删除或替换版本时清理旧向量。

### 4.4 知识库问答流程

```text
用户进入某个知识库
  → 输入问题
  → 前端校验非空
  → 后端验证当前用户权限
  → 只检索该知识库的 indexed 文档块
  → 对问题生成向量
  → 查询 Top-K 相关文档块
  → 组装带来源上下文的 Prompt
  → 调用 LLM
  → SSE 返回 token/citation/done
  → 前端展示答案和来源
```

无依据路径：

- 没有 indexed 文档：提示先上传并完成索引；
- 检索结果不足：提示当前知识库没有足够依据；
- LLM 失败：展示失败状态，不伪造完整答案。

### 4.5 故障分析流程

```text
用户进入故障分析页
  → 选择知识库
  → 填写故障标题和错误日志
  → 前端校验必填项
  → 后端校验权限
  → 检索技术文档
  → 构造故障分析 Prompt
  → LLM 生成分析
  → SSE 流式返回
  → 前端展示可能原因和排查步骤
  → 成功完成后保存 incident 记录
```

与普通问答的区别：

- 普通问答回答用户提出的知识问题；
- 故障分析必须围绕标题、日志、可能原因、排查步骤和证据组织；
- 两者可以复用检索和 LLM 服务，但保存的业务记录不同。

## 5. 前后端职责边界

### 前端负责

- 页面展示和路由；
- 表单基础校验；
- Token 携带和登录态处理；
- 上传进度和状态展示；
- SSE 事件解析和逐步渲染；
- 错误、空状态和加载状态展示。

### 后端负责

- 身份认证和权限判断；
- 文件类型、大小和路径安全校验；
- 文档解析、切分、Embedding 和 Chroma 写入；
- 数据库事务和文档状态；
- 知识库范围过滤；
- LLM 调用和异常转换；
- 故障分析记录保存。

前端不能作为权限边界。即使前端隐藏了某个知识库，后端仍必须拒绝越权请求。

## 6. 页面与业务对象关系

```text
用户
  └── 知识库
        ├── 文档
        │     └── 文档版本
        │            └── 文档块 → Chroma 向量
        ├── 问答会话/消息（P1）
        └── 故障分析记录
```

说明：具体表名、字段、外键和向量元数据在阶段 5 的数据库设计中冻结，本图只表达业务关系。

## 7. 前端最小导航结构

```text
App
├── 登录/注册
└── 主布局
    ├── 知识库列表
    ├── 当前知识库
    │   ├── 工作台
    │   ├── 文档管理
    │   ├── 知识库问答
    │   └── 故障分析
    ├── 分析历史
    └── 个人信息/退出
```

## 8. 设计取舍

### 当前采用

- 知识库作为 MVP 主要容器；
- 模块化单体；
- 文档索引状态显式保存；
- 普通问答和故障分析共用检索基础能力，但使用不同业务输入和记录；
- P0 先做基本列表和状态反馈，完整详情与版本页放到 P1。

### 当前不采用

- 第一版不引入项目、工作空间两层嵌套；
- 第一版不做复杂团队协作权限；
- 第一版不做自动执行修复命令；
- 第一版不把故障分析记录自动写回知识库；
- 第一版不为高级检索设计复杂页面。

## 9. 阶段 3 评审确认项

阶段 3 已确认以下决策：

1. 以知识库作为 MVP 的主要容器，不单独实现项目/工作空间页面；
2. 接受当前页面路径、页面职责和 P0/P1 页面划分；
3. 普通问答和故障分析复用检索能力，但保存为不同业务记录；
4. 文档索引状态和 SSE 的成功、失败、中断状态都在页面展示；
5. 先做功能和状态闭环，视觉细节在前端开发阶段确定。

确认结果：以上五项全部接受。进入阶段 4：技术选型和系统架构。
