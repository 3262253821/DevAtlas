## 已确认技术栈

- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia；
- 后端：Python 3.13.2、FastAPI、Uvicorn、Pydantic、SQLAlchemy 2、Alembic；
- 关系型数据库：MySQL 8.0.41，`127.0.0.1:3306`，用户 `root`，数据库名 `dev_atlas`；
- 向量库：Chroma Persistent Client；
- Embedding：本地 `BAAI/bge-small-zh-v1.5`；
- LLM：DeepSeek，目标模型 `deepseek-v4-flash`；正式开发前先做最小普通/流式请求验证；
- 认证：JWT Bearer；
- 流式输出：SSE；
- 架构：模块化单体；
- Docker：阶段 9 再决定是否安装；
- Redis：主链路稳定后再按明确用途加入；
- GitHub：正式开发时按可验证功能提交，基础版本稳定后连接远程仓库。

## 不能丢失的架构决策

- MySQL 保存业务事实，Chroma 只负责向量检索；
- 文档版本状态决定向量是否可以参与默认检索；
- 权限必须同时覆盖 MySQL 查询和 Chroma metadata 过滤；
- 普通问答和故障分析复用 RAG 基础能力，但保存不同业务记录；
- LLM 调用封装在独立 Service，不散落在路由中；
- MVP 不引入微服务、消息队列、Agent、MCP、Milvus、Reranker；
- Docker、Redis 和高级检索不是当前主链路的阻塞条件。

## 阶段 5 前置事实

- 项目代码目录仍为空骨架：`backend`、`frontend`、`tests`、`docs`、`others`；
- 当前只设计接口和表，不开始初始化业务代码；
- 密码、DeepSeek API Key 等敏感信息不进入文档和 Git。
