# DevAtlas 开发与测试指南

> **适用范围**：本文档面向在 **Windows + PowerShell** 下参与 DevAtlas 开发、联调和验收的人员。
> 项目定位是**开发环境 MVP**，本文所有命令均在本地 development 环境执行，
> 不涉及生产环境部署与上线。
>
> **项目根目录**：`E:\RagKnowledgeSystem`。除特别说明外，所有命令都在**项目根目录**执行。

## 1. 开发环境

### 1.1 环境要求

| 依赖 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 | 命令全部使用 PowerShell |
| PowerShell | 建议 **7.x（pwsh）** | 涉及 `Invoke-WebRequest -Form` 的命令需要 PowerShell 6+ |
| Python | **3.13** | 后端运行时 |
| Node.js | **20 及以上** | 前端构建与开发服务器 |
| MySQL | **8.x** | 业务数据库，本地约定 `127.0.0.1:3306`，库名 `dev_atlas` |
| 内存 | 建议 8 GB 以上 | 首次加载 BGE Embedding 模型占用较多内存 |
| 磁盘 | 建议预留 2 GB | 模型缓存、上传文件与 Chroma 持久化数据 |

> 请保证网络可达；模型会缓存在本地，后续启动不再重复下载。无 GPU 时自动使用 CPU 推理。

### 2.4 CORS 注意事项

`backend/app/main.py` 的 CORS 白名单只包含：

```text
http://127.0.0.1:5173
http://localhost:5173
```

并设置 `allow_credentials=True`、`allow_methods=["*"]`、`allow_headers=["*"]`。

**换端口或换域名必须同步修改 CORS 白名单**，否则浏览器会直接拦截请求
（典型现象：`curl` 能通，浏览器控制台报 CORS 错误）。

## 6. 浏览器联调

### 6.1 启动顺序

1. 确认 MySQL 服务运行，且已执行 `alembic upgrade head`；
2. 启动后端（见 2.2），访问 `http://127.0.0.1:8000/health` 确认返回正常；
3. 启动前端（见 2.3），打开 `http://127.0.0.1:5173`。

### 6.2 主链路联调路径

```text
注册 → 登录 → 创建知识库 → 上传文档 → 等待状态变为 indexed
→ 知识库问答（SSE 流式 + 引用） → 故障分析（SSE 流式）
→ 故障历史查看 → 删除记录 → 退出登录
```

对应页面路由：

| 路由 | 页面 |
| --- | --- |
| `/login`、`/register` | 登录、注册 |
| `/legal/terms`、`/legal/privacy` | 条款与隐私说明 |
| `/workspaces` | 我的知识库（列表、创建、删除） |
| `/knowledge/:id` | 知识库工作台 |
| `/knowledge/:id/documents` | 文档管理 |
| `/knowledge/:id/qa` | 知识库问答 |
| `/knowledge/:id/incidents/new` | 发起故障分析 |
| `/incidents` | 故障历史 |

### 6.3 联调观察点

- 未登录直接访问受保护路由，应跳转 `/login` 并带上 `redirect` 查询参数；
- 已登录访问 `/login` 或 `/register`，应跳回 `/workspaces`；
- 上传后文档状态应从 `pending` 变为 `indexed`，切片数大于 0；
- 问答页回答应**逐字增长**（说明是流式），结束后出现引用列表；
- 模型输出使用 markdown-it 渲染，且**关闭原始 HTML 解析**（防止模型输出被当作 HTML 执行）。

浏览器端查看 SSE 原始流：打开开发者工具 → Network → 选中 `qa/stream` 或
`incidents/stream` 请求 → 查看 EventStream / Response 面板。

### 7.2 参数

| --- | --- | --- |

| `--password` | 环境变量 `DEVATLAS_SEED_PASSWORD`，兜底 `DevAtlas123!` | 开发账号密码 |
| `--knowledge-base-name` | 环境变量 `DEVATLAS_SEED_KB_NAME`，兜底 `DevAtlas 开发演示知识库` | 演示知识库名称 |

```powershell

```

### 7.3 幂等行为

- **用户**：按用户名查找，已存在则**不覆盖已有密码**，只把 `is_active` 补成 `True`；
  不存在才创建；
- **知识库**：按 `(owner_id, name)` 查找，已存在则直接复用；
- **文档**：先计算 `tests/` 源文件的 SHA-256，再与已有版本比对：
  - 已存在且状态为 `indexed` → **跳过**；
  - 已存在但状态为 `failed` → 调用 `reindex_document` **重新索引**；
  - 不存在 → 复制到上传目录并执行 `ingest_document` 导入；
- 因此脚本可以重复执行，不会因为相同文件内容而重复创建文档版本。

### 7.4 安全约束

- **`APP_ENV` 为 `production` 或 `prod` 时，脚本直接 `SystemExit` 拒绝执行**；
- 脚本只面向本地 development 环境，**不要在生产数据库执行**；
- 默认账号与默认密码只用于**本地开发**。`DevAtlas123!` 是脚本内的开发占位值，
  不是任何真实环境凭据；不要把它写进生产配置、不要提交真实密码到脚本或 Git。

## 9. 版本切换验证

**目标**：确认"内容变化会创建新版本"，且"新版本只有在索引成功后才成为当前版本"。

### 9.1 步骤

1. 先上传 `tests/订单服务故障排查手册.md`，等状态变为 `indexed`，记为 **v1**；
2. 复制该文件到临时目录并**修改其中一句话**：

```powershell
Set-Location E:\RagKnowledgeSystem
New-Item -ItemType Directory -Force -Path others\tmp | Out-Null
Copy-Item -LiteralPath "tests\订单服务故障排查手册.md" -Destination "others\tmp\订单服务故障排查手册.md" -Force
Add-Content -LiteralPath "others\tmp\订单服务故障排查手册.md" -Value "`n（本地验证用追加内容，用于产生新的 SHA-256。）" -Encoding utf8
```

3. 把修改后的同名文件上传到同一个知识库：

```powershell
$upload = Invoke-RestMethod -Method Post `
  -Uri "$base/knowledge-bases/$kbId/documents" `
  -Headers $headers `
  -Form @{ file = Get-Item -LiteralPath "E:\RagKnowledgeSystem\others\tmp\订单服务故障排查手册.md" }

$upload | Select-Object id, filename, version_number, status, chunk_count, duplicate
```

### 9.2 预期结果

| 观察项 | 预期 |
| --- | --- |
| 响应 `id` | 与 v1 的 `document_id` **相同**（同一个逻辑文档，不是新文档） |
| `version_number` | 由 1 变为 **2** |
| `duplicate` | `false` |
| `status` | 处理成功后为 `indexed` |
| 版本列表 | `GET /knowledge-bases/{kbId}/documents/{documentId}/versions` 返回两条记录 |

```powershell
$docId = $upload.id
Invoke-RestMethod -Method Get -Uri "$base/knowledge-bases/$kbId/documents/$docId/versions" -Headers $headers |
  Format-Table id, version_number, status, chunk_count, file_sha256
```

```powershell
Invoke-RestMethod -Method Get -Uri "$base/knowledge-bases/$kbId/documents/$docId" -Headers $headers |
  Select-Object id, filename, @{n="current_version";e={$_.current_version.version_number}}, @{n="status";e={$_.current_version.status}}
```

`current_version.version_number` 应为 **2**，说明切换时机正确。

### 9.3 对应的自动化验证

`tests/test_document_ingestion_version_switch.py::test_successful_ingestion_switches_current_version_only_after_indexing`
断言 `result.version.status == "indexed"`、`chunk_count == 1`，
且 `document.current_version_id` 已被切换到新版本。

## 10. 失败回退验证

**目标**：确认新版本处理失败时**旧版本仍然可用**，失败原因被保留。

### 10.1 自动化验证（推荐先跑）

```powershell
Set-Location E:\RagKnowledgeSystem
python -m pytest tests/test_document_ingestion_version_switch.py -v
```

该文件覆盖四类失败／成功路径：

| 测试用例 | 断言的关键行为 |
| --- | --- |
| `test_failed_ingestion_keeps_previous_current_version` | 解析失败 → 版本 `failed`、错误原因保留、`current_version_id` 仍是旧值 |
| `test_successful_ingestion_switches_current_version_only_after_indexing` | 成功 → 才切换 `current_version_id` |
| `test_embedding_failure_keeps_previous_current_version` | Embedding 失败 → 旧版本仍生效 |
| `test_vector_store_failure_cleans_up_vectors_and_keeps_previous_version` | Chroma 写入失败 → 触发向量补偿清理，旧版本仍生效 |
| `test_duplicate_content_does_not_create_version_and_removes_temp_file` | 重复内容 → `duplicate=True`、不创建版本、临时文件被删除 |

### 10.2 手动验证（可复现的真实失败）

利用"同名文件 + 非 UTF-8 内容"制造一次真实的解析失败。
因为文件名与已有的 `订单服务故障排查手册.md` 相同，它会收敛到同一条逻辑文档。

```powershell
Set-Location E:\RagKnowledgeSystem
New-Item -ItemType Directory -Force -Path others\tmp | Out-Null

# 写入 UTF-16 字节：该内容不是合法 UTF-8，解析阶段会失败
$bytes = [byte[]](0xFF, 0xFE, 0x41, 0x00, 0x42, 0x00, 0x43, 0x00)
[System.IO.File]::WriteAllBytes("E:\RagKnowledgeSystem\others\tmp\订单服务故障排查手册.md", $bytes)

$failedUpload = Invoke-RestMethod -Method Post `
  -Uri "$base/knowledge-bases/$kbId/documents" `
  -Headers $headers `
  -Form @{ file = Get-Item -LiteralPath "E:\RagKnowledgeSystem\others\tmp\订单服务故障排查手册.md" }

$failedUpload | Select-Object id, version_number, status, chunk_count, error_message

# 该文件名与第 9 节相同，因此收敛到同一条逻辑文档
$docId = $failedUpload.id
```

### 10.3 预期结果

| 观察项 | 预期 |
| --- | --- |
| `status` | `failed` |
| `error_message` | 非空，内容为解析错误（类似 `The document is not valid UTF-8 text`） |
| `chunk_count` | `0` |
| `version_number` | 比上一次成功版本递增（失败版本同样占用版本号） |

再确认**旧版本仍然生效**：

```powershell
Invoke-RestMethod -Method Get -Uri "$base/knowledge-bases/$kbId/documents/$docId" -Headers $headers |
  Select-Object @{n="current_version";e={$_.current_version.version_number}}, @{n="status";e={$_.current_version.status}}, @{n="chunk_count";e={$_.current_version.chunk_count}}
```

预期：`status` 仍是 `indexed`，`version_number` 仍是**上一个成功版本**，
说明失败版本没有顶掉可检索版本。

最后确认检索仍然命中该文档（见第 12 节检索来源验证）。

### 10.4 重新索引验证

对失败版本调用重新索引（修复源文件后即可成功；不修复则再次失败）：

```powershell
Invoke-RestMethod -Method Post `
  -Uri "$base/knowledge-bases/$kbId/documents/$docId/reindex" `
  -Headers $headers | Select-Object document_id, version_id, version_number, status, chunk_count, error_message
```

- 源文件仍然损坏时：返回 **200**，`status` 仍为 `failed`（重新索引本身是成功执行的）；
- 源文件已修复时：`status` 变为 `indexed`，且 `current_version_id` 切换到该版本；
- 如果该文档当前**没有** `failed` 版本，接口返回 **409 Conflict** —— 这是正常业务结果，不是错误。

```powershell
# 对当前没有 failed 版本的文档调用重新索引，观察 409
# 先用一个状态正常的文档 ID 替换 $okDocId
$okDocs = Invoke-RestMethod -Method Get -Uri "$base/knowledge-bases/$kbId/documents?page=1&page_size=100" -Headers $headers
$okDocId = ($okDocs.items | Where-Object { $_.current_version.status -eq "indexed" } | Select-Object -First 1).id

try {
```

## 13. SSE 验证

**目标**：验证事件类型、顺序和字段。

### 13.1 事件契约

| 事件 | 数据字段 |
| --- | --- |
| `token` | `{"text": "..."}` |
| `citation` | `{"index","document_id","version_id","version_number","chunk_index","filename","distance"}` |
| `done`（问答） | `{"conversation_id": <请求值或 null>, "message_id": null}` |
| `done`（故障） | `{"incident_id": <id>, "status": "completed"}` |
| `error` | `{"code":"LLM_SERVICE_ERROR","message":"大模型服务暂时不可用"}` |

正常顺序：多个 `token` → 多个 `citation` → `done`。
响应 `Content-Type` 为 `text/event-stream`，并带有
`Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`。

### 13.2 知识库问答 SSE

用 `curl.exe` 写文件再读取，可以避免 PowerShell 控制台编码把中文显示成乱码：

```powershell
Set-Location E:\RagKnowledgeSystem
New-Item -ItemType Directory -Force -Path others | Out-Null

$qaBody = '{"question":"订单服务返回 502 时，应该按照什么顺序排查？","top_k":3,"conversation_id":null}'

curl.exe -N -s -o others\sse-qa.txt -X POST `
  "http://127.0.0.1:8000/api/v1/knowledge-bases/$kbId/qa/stream" `
  -H "Authorization: Bearer $($login.access_token)" `
  -H "Content-Type: application/json" `
  --data-raw $qaBody

Get-Content -LiteralPath others\sse-qa.txt -Encoding utf8
```

**预期**：能看到形如下面的顺序（`token` 多次出现，中文正常显示）：

```text
event: token
data: {"text":"根据"}

event: token
data: {"text":"知识库"}

...

event: citation
data: {"index":1,"document_id":2,"version_id":3,"version_number":2,"chunk_index":29,"filename":"订单服务故障排查手册.md","distance":0.55}

event: done
data: {"conversation_id":null,"message_id":null}
```

**无来源时的预期**：只出现一条 `token`（内容为「当前知识库中没有检索到与该问题相关的内容。」）
和一条 `done`，**不调用大模型**。

**LLM 失败时的预期**：出现 `error` 事件，
`{"code":"LLM_SERVICE_ERROR","message":"大模型服务暂时不可用"}`。
（常见原因：`DEEPSEEK_API_KEY` 未配置、网络不通、额度用尽。）

### 13.3 故障分析 SSE

```powershell
Set-Location E:\RagKnowledgeSystem

$incidentBody = '{"title":"订单服务生产环境返回 502","content":"gateway ERROR upstream prematurely closed connection\nPOST /api/orders returned 502"}'

curl.exe -N -s -o others\sse-incident.txt -X POST `
  "http://127.0.0.1:8000/api/v1/knowledge-bases/$kbId/incidents/stream" `
  -H "Authorization: Bearer $($login.access_token)" `
  -H "Content-Type: application/json" `
  --data-raw $incidentBody

Get-Content -LiteralPath others\sse-incident.txt -Encoding utf8
```

**预期**：`token…` → `citation…` → `done`，
且 `done` 数据为 `{"incident_id": <id>, "status": "completed"}`。

**故障分析的异常表现与前缀差异（重要）**：

| 情形 | 表现 |
| --- | --- |
| 检索失败 | **HTTP 503**（抛 HTTPException，`incident` 被标记 `failed`）—— **不是** SSE `error` 事件 |
| LLM 失败 | SSE `error` 事件，`incident` 被标记 `failed` |
| 客户端中途断开 | `incident` 被标记 `cancelled` |
| 知识库无相关内容 | 一条中文提示 `token` + `done`，`incident` 标记 `completed` |

> 排查提示：SSE 是"HTTP 200 已经开始返回"之后才可能出错的长连接。
> 如果**请求本身**就返回了非 200，说明失败发生在流建立之前（例如 503 检索失败）；
> 如果请求是 200，但流里出现 `error` 事件，说明失败发生在生成阶段。

### 13.4 故障历史验证

```powershell
Invoke-RestMethod -Method Get -Uri "$base/incidents?page=1&page_size=10" -Headers $headers |
  Select-Object -ExpandProperty items |
  Format-Table id, title, status, model_name, created_at, completed_at

Invoke-RestMethod -Method Get -Uri "$base/incidents/1" -Headers $headers |
  Select-Object id, title, status, result, error_message, citations
```

**预期**：列表按 `owner_id` 过滤（只看到自己的记录）；
详情包含 `input_content`、`result`、`error_message` 和 `citations`
（`citations` 元素为 `{citation_index, document_chunk_id}`）。

### 13.5 排查 SSE 时的常见坑

- **不能用 `EventSource`**：`EventSource` 无法自定义 `Authorization` 头，且这里必须是 POST。
  前端使用 `fetch` + `ReadableStream`（见 `frontend/src/api/sse.ts`）；
- **跨 chunk 的事件边界**：一个 SSE 事件块可能被 TCP 分片拆开，
  必须按空行切分并把未闭合的最后一段留在缓冲区，流结束时再兜底解析一次；
- **中文乱码**：用 `curl.exe -o file` + `Get-Content -Encoding utf8` 读取，
  不要直接管道输出到控制台。

## 14. 删除清理验证

**目标**：确认删除文档后，MySQL 记录、原始文件和 Chroma 向量都被清理，
**旧向量不会再出现在检索结果中**。

### 14.1 步骤

1. 先上传 `tests/DevAtlas团队入门手册.txt`，等状态变为 `indexed`；
2. 在该文档中找一个**独有的关键词**（例如手册里才有的流程名称），用它提问一次，
   确认 `sources` 中出现了该文件：

```powershell

  -ContentType "application/json" `
  -Body '{"question":"忘记密码后应该通过什么流程处理？","top_k":5}'

$before.sources | Select-Object @{n="file";e={$_.filename}}, @{n="version";e={$_.version_number}}, distance
```

3. 记录该文档 ID，然后删除：

```powershell
$docs = Invoke-RestMethod -Method Get -Uri "$base/knowledge-bases/$kbId/documents?page=1&page_size=100" -Headers $headers
$docs.items | Format-Table id, filename, @{n="status";e={$_.current_version.status}}

$docId = ($docs.items | Where-Object { $_.filename -eq "DevAtlas团队入门手册.txt" } | Select-Object -First 1).id

$del = Invoke-WebRequest -Method Delete -Uri "$base/knowledge-bases/$kbId/documents/$docId" -Headers $headers
"删除 status = $($del.StatusCode)"   # 期望 204
```

4. 再次提问同一个问题，检查 `sources`：

```powershell
$after = Invoke-RestMethod -Method Post -Uri "$base/knowledge-bases/$kbId/search" -Headers $headers `
  -ContentType "application/json" `
  -Body '{"question":"忘记密码后应该通过什么流程处理？","top_k":5}'

$after.sources | Select-Object @{n="file";e={$_.filename}}, @{n="version";e={$_.version_number}}, distance
```

### 14.2 预期结果

| 观察项 | 预期 |
| --- | --- |
| 删除接口 | `204 No Content` |
| 文档列表 | 该文档不再出现 |
| 再次检索 | `sources` 中**不再出现** `DevAtlas团队入门手册.txt` |
| 版本接口 | `GET .../documents/{docId}/versions` 返回 `404` |

> 如果删除后仍能检索到旧内容，说明向量清理没有生效，
> 需要检查 `DELETE` 是否真的走到了 Chroma 清理分支。

### 14.3 清理顺序（实现说明）

`delete_document` 的真实顺序是：

```text
先清理 Chroma 向量（delete_vectors，使用 document_chunks.vector_id）
→ 再删除原始文件（others/uploads 下的存储文件）
→ 最后删除 MySQL 记录（documents 删除后由外键 CASCADE 连带 versions / chunks）
```

这个顺序是刻意的：如果先删 MySQL，就会丢失清理 Chroma 所需的 `vector_id`。

### 14.4 重新索引时的清理

失败版本调用 `reindex` 时，也会先删除该版本可能残留的旧向量与 chunk 记录，
再重置为 `pending` 重新走完整流程。重建期间保留原 `current_version_id`，
只有成功后才会切换。
