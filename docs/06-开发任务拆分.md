# 阶段 6：开发任务拆分

## 文档状态

- 版本：v0.1（阶段 6 已确认）
- 项目：DevAtlas｜研发知识协同平台
- 前置文档：阶段 1 至阶段 5 文档
- 当前状态：已由用户确认，未初始化业务代码

## 1. 阶段目标

把已经确认的 PRD、页面流程、技术架构、API 和数据库设计拆成可以逐项实现、逐项测试和逐项提交的任务。

阶段 6 不实现业务代码，重点是确定：

- 先做什么；
- 哪些任务依赖前置任务；
- 每项任务怎么判断完成；
- 每项任务测试什么；
- 哪些内容可以使用 AI 辅助生成，哪些核心逻辑必须由用户理解和验收。

## 2. 开发原则

- 先建立可运行的最小后端，再逐步接入业务；
- 先完成 P0 主链路，再做 P1 历史和页面增强；
- 每个功能都经过“创建文件 → 运行 → 测试 → 解释 → 小修改”；
- 路由层不堆业务逻辑；
- 数据库修改必须通过 Alembic；
- 每个可验证功能完成后再 Git commit；
- 不为了赶进度跳过错误路径和权限测试。

## 3. 阶段任务总览

### T01：项目基础初始化

内容：初始化本地 Git、创建后端 Python 结构、创建前端 Vue 项目、创建 `.gitignore`、`.env.example` 和 README 初稿、建立健康检查接口。

依赖：无。

完成标准：后端健康接口返回成功，前端页面可以打开，敏感文件不会被 Git 跟踪。

### T02：环境和配置模块

内容：配置 MySQL、JWT、DeepSeek、Chroma、上传目录和 Embedding 模型；实现配置缺失时的明确错误。

依赖：T01。

完成标准：服务能读取非敏感配置，真实密钥不进入代码。

### T03：数据库基础和迁移

内容：创建 SQLAlchemy Base、Engine、Session；配置 Alembic；创建第一批 P0 模型；生成并执行初始迁移。

依赖：T02。

完成标准：`dev_atlas` 中 P0 表创建成功，能创建和关闭数据库会话。

### T04：用户注册、登录和当前用户

内容：用户模型、密码哈希、注册、登录、JWT 生成/解析、`get_current_user`、当前用户接口。

依赖：T03。

测试点：重复用户名、错误密码、无 Token、失效 Token、正常登录。

完成标准：Swagger 和接口测试都能完成注册、登录和受保护接口访问。

### T05：知识库 CRUD 和所有者权限

内容：创建、列表、详情、删除知识库；所有查询带 owner_id 权限条件。

依赖：T04。

测试点：用户 A 不能读取、修改或删除用户 B 的知识库。

完成标准：数据库权限条件和接口返回符合 API 契约。

### T06：文件上传和安全校验

内容：上传目录、扩展名白名单、文件大小限制、文件名规范化、路径穿越防护、SHA-256、原始文件保存。

依赖：T05。

测试点：合法文件、不支持格式、超大文件、空文件、重复文件名、恶意路径。

完成标准：合法文件能保存，非法文件不会进入业务处理。

### T07：文档解析、切分和版本

内容：TXT/Markdown/PDF 解析、文本切分、逻辑文档和版本、`pending/indexed/failed` 状态、重复内容幂等、内容变化新版本。

依赖：T06、T03。

完成标准：版本关系正确，失败状态和原因可查询。

### T08：Embedding 和 Chroma 入库

内容：加载 `BAAI/bge-small-zh-v1.5`、生成文档块向量、写入 Chroma、保存 vector_id 和 metadata、更新 indexed、失败补偿和旧向量清理。

依赖：T07。

测试点：正常入库、重复入库、Embedding 失败、Chroma 失败、重新索引、删除清理。

完成标准：MySQL、文件系统和 Chroma 状态保持可解释的一致性。

### T09：文档查询、详情、删除和重新索引

内容：文档列表、详情、版本列表、删除、重新索引失败版本和权限过滤。

依赖：T08。

完成标准：前端能看到状态，删除后不能检索到旧向量。

### T10：基础 RAG 检索

内容：问题 Embedding、Chroma Top-K、knowledge_base_id 过滤、indexed 版本过滤、上下文组装和引用来源结构。

依赖：T08、T09。

完成标准：固定问题能返回相关文档块和来源 metadata。

### T11：DeepSeek 普通调用和 Prompt

内容：最小 `deepseek-v4-flash` 普通请求、LLM Service、RAG Prompt、超时和错误转换、敏感信息保护。

依赖：T02、T10。

完成标准：真实配置能完成一次带上下文回答；失败时返回统一错误。

### T12：知识库问答 SSE

内容：POST SSE、`token/citation/done/error` 事件、权限和参数校验、前端流式解析、可中断和失败状态。

依赖：T11。

完成标准：浏览器页面能逐步展示回答并显示来源。

### T13：故障分析和 incident 记录

内容：标题和日志校验、故障分析 Prompt、故障分析 SSE、`incidents` 和 citations 保存、completed/failed/cancelled 状态。

依赖：T12、T03。

完成标准：提交故障日志后能流式得到原因、步骤和来源，成功后数据库有记录。

### T14：Vue 页面和前后端联调

内容：登录注册、Pinia 登录态、知识库列表和创建、文档上传和状态、问答页、故障分析页、SSE 渲染和错误状态。

依赖：T04、T05、T09、T12、T13。

完成标准：从登录到上传、问答、故障分析的完整浏览器流程跑通。

### T15：测试、修复和交付材料

内容：pytest 接口测试、权限测试、上传异常测试、RAG 固定问题集、README、架构图、数据库图、截图和真实测试记录。

依赖：T14。

完成标准：核心主链路、异常路径和权限边界有可复现验证。

## 5. 每个任务的学习闭环

每次开始任务时：

1. 说明业务目标和前置依赖；
2. 指定用户创建或修改的文件；
3. 给出一小步代码和运行命令；
4. 用户自己执行并发送结果；
5. 解释实际输出和整体调用流程；
6. 逐行分析核心代码；
7. 做一个正常或异常场景测试；
8. 完成任务后再提交 Git。

## 6. Git 提交节奏

建议提交：

- `chore: initialize project structure`
- `feat: add health check`
- `feat: add database and alembic setup`
- `feat: add user authentication`
- `feat: add knowledge base permissions`
- `feat: add document upload`
- `feat: add document indexing`
- `feat: add rag retrieval`
- `feat: add streaming qa`
- `feat: add incident analysis`
- `test: add api and permission tests`

每次提交前检查：功能能运行、测试通过、没有密钥/密码/上传文件/本地向量数据，且提交信息能说明本次变化。
