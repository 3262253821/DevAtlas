DevAtlas 团队研发知识协同平台
文档类型：团队入门与日常操作手册
版本：v1.0

一、平台定位

DevAtlas 用于集中管理研发团队的服务文档、部署说明、接口约定和故障排查经验。平台的核心流程是：创建知识库，上传研发文档，系统解析并切分文本，生成向量并建立索引，用户再通过自然语言问题检索相关内容。

平台不会把所有文档直接拼接给大模型。提问时，系统先将问题转换为向量，在当前知识库中检索最相似的若干文档切片，然后把切片和问题一起交给大模型生成答案。回答页面会同时显示引用文件、切片编号和距离值，便于研发人员回看原始依据。

二、第一次使用流程

1. 注册账号
用户名长度必须为 3 到 50 个字符，密码长度必须为 8 到 128 个字符。确认密码必须和第一次输入的密码完全一致。用户名已经存在时，注册会失败并提示用户更换名称。

2. 登录平台
登录成功后，服务端返回 Bearer 类型的 JWT 访问令牌。前端将令牌保存到登录状态中，访问知识库、文档和问答接口时自动放入 Authorization 请求头。退出登录会清理本地会话。

3. 创建知识库
建议每个知识库对应一个服务、一个业务域或一个团队。例如可以创建“订单服务研发知识库”，描述填写“保存订单服务的架构、接口、部署和故障处理资料”。知识库之间相互隔离，用户只能访问自己拥有的知识库。

4. 上传文档
当前支持 TXT、Markdown 和 PDF 文件。上传文件会经过扩展名白名单、文件大小、空文件和路径安全检查。系统会计算文件 SHA-256 指纹，用于判断内容是否重复。

5. 等待索引完成
文档版本通常会经历 pending、indexed 或 failed 状态。indexed 表示文本已经解析、切分、向量化并写入向量数据库，可以被问答检索。failed 表示处理失败，需要查看错误原因或点击重新索引。

三、文档版本规则

一个逻辑文档代表文件的长期身份，例如“订单服务部署手册”。同一个逻辑文档可以有多个版本。文件名相同但内容发生变化时，系统创建新的版本号；内容完全一致时，系统判定为 duplicate，不重复创建版本。

判断内容是否变化依赖 SHA-256。SHA-256 不是用来加密文件，而是生成内容指纹。只要文件内容发生变化，指纹通常就会变化。删除文档时，系统同时清理数据库记录、原始文件和已经写入向量库的向量，避免旧内容继续被召回。

四、推荐提问方式

问题越具体，检索结果通常越容易命中。推荐提问：

- 订单服务返回 502 时，先检查哪些组件？
- 忘记密码后应该通过什么流程处理？
- 文档状态一直是 pending 可能有哪些原因？
- 如何判断一个上传文件是否和旧版本内容重复？
- 问答结果中的 distance 数值代表什么？
- knowledge_base_id 在权限校验中有什么作用？

不建议只输入“这是干嘛的”，因为缺少业务对象和上下文，检索结果可能不够准确。

五、权限边界

每个知识库都有 owner_id。后端查询知识库、上传文档、发起问答和故障分析时，都会同时校验当前用户身份和知识库所有者。即使用户猜到了其他知识库的数字 ID，也不能读取或修改其他用户的数据。

六、问答结果如何理解

回答区域展示模型生成的自然语言结果。引用来源展示检索命中的文件和切片。Top-K 表示最多向量检索多少个相似切片，不代表模型只能输出 K 句话。distance 是向量距离，通常越小表示语义越接近，但具体范围取决于向量数据库使用的距离度量。

回答通过 SSE 流式传输。前端会连续收到 token、citation、done 或 error 事件。token 事件携带一小段回答文字，前端把这些文字按顺序拼接起来，所以浏览器看到的回答会逐步增长。

七、日常排查建议

如果回答与文档无关，先检查文档是否为 indexed，再检查提问是否包含文档中的关键词或业务对象。随后查看引用来源和 distance。如果没有任何引用，可能是知识库没有可用索引，或者问题与现有文档的语义差异过大。

如果上传后状态为 failed，先查看错误原因，再使用重新索引。不要直接重复上传同一个文件，因为内容指纹相同的文件会被识别为 duplicate。

如果页面提示未授权，先重新登录并确认 Authorization 请求头存在。不要把 JWT、DeepSeek API Key 或数据库密码写入文档、截图和公开仓库。
