# DevAtlas MVP 一条龙验收流程

这份清单模拟一个第一次使用 DevAtlas 的新用户。测试前假设数据库中已经删除旧测试知识库，但保留或新建一个测试账号都可以。

## 0. 测试资料

在文档上传页面依次使用以下文件：

1. `DevAtlas团队入门手册.txt`
2. `订单服务故障排查手册.md`
3. `DevAtlas系统架构与操作规范.pdf`

TXT 和 Markdown 主要覆盖中文业务内容，PDF 是为了验证 PDF 解析链路而准备的英文技术资料。三份文档内容互相补充，适合验证不同文件格式、切片、向量检索和引用来源。

## 1. 注册新用户

1. 打开前端登录页，进入注册页面。
2. 输入一个没有使用过的用户名，例如 `devatlas_demo`。
3. 输入密码，长度至少 8 个字符，例如 `DevAtlas@2026`。
4. 再次输入相同密码。
5. 点击创建账号。

预期结果：页面即时校验通过，注册成功后跳转到登录页。

额外验证：输入 `aa`、长度超过 50 的用户名、`123456`、两次不同的密码，页面应在输入过程中直接显示错误提示，不能等到提交后才发现。

## 2. 登录

1. 使用刚注册的账号登录。
2. 勾选“我同意服务协议与隐私政策”。
3. 点击进入工作区。

预期结果：进入“我的知识库”工作区首页，左侧固定导航栏显示知识库和故障历史。

额外验证：不勾选协议时按钮为灰色，点击会提示，不能发送登录请求。

## 3. 创建知识库

在“我的知识库”页面点击“新建知识库”，填写：

- 名称：`订单服务研发知识库`
- 描述：`保存订单服务架构、接口、部署和故障排查经验`

预期结果：

- 知识库总数变为 1；
- 最近使用区域出现该知识库；
- 全部知识库列表出现一行记录；
- 点击“进入工作台”可以进入该知识库详情页。

## 4. 认识知识库工作台

详情页的三个核心入口分别是：

- 文档管理：上传文档、查看版本和索引状态、重新索引、删除文档；
- 知识库问答：基于当前知识库的 indexed 文档进行 RAG 问答；
- 故障分析：输入故障标题和日志，让系统结合知识库生成排查建议。

页面上的统计卡片含义：

- 文档总数：当前知识库中的逻辑文档数量；
- 已完成索引：状态为 indexed、可以被检索的文档数量；
- 需要关注：状态为 pending 或 failed 的文档数量。

## 5. 上传和索引文档

进入“文档管理”，依次上传三份测试资料。

每上传一份，观察当前版本、状态和切片数：

- `pending`：正在解析、切分、Embedding 或 Chroma 入库；
- `indexed`：已完成索引，可以参与问答；
- `failed`：某个处理环节失败，需要查看原因或重新索引。

预期结果：三份文件最终都显示 `indexed`，并且切片数大于 0。

重复文件验证：再次上传完全相同的 `DevAtlas团队入门手册.txt`，预期提示内容未变化、返回 `duplicate=true`，不会凭空创建新的内容版本。

内容变化验证：复制 TXT 文件，修改其中一句话后重新上传。预期系统将同一个逻辑文档创建一个新的版本号，而不是创建无法关联的新逻辑文档。

## 6. 知识库问答

进入“知识库问答”，先等待所有文档为 indexed，再依次提问：

### 问题 A：检索中文入门手册

```text
忘记密码后应该通过什么流程处理？
```

预期：回答提到登录页重置密码或账号恢复流程，并在引用来源中出现 `DevAtlas团队入门手册.txt`。

### 问题 B：检索故障排查手册

```text
订单服务返回 502 时，应该按照什么顺序排查？
```

预期：回答包含健康检查、网关到 8080 端口、错误日志、数据库连接池和网关超时等内容，引用来源出现 `订单服务故障排查手册.md`。

### 问题 C：验证知识库边界

```text
公司明年的股票价格是多少？
```

预期：系统应该说明当前知识库没有足够依据，不能编造答案。引用距离可能较大，或者回答明确提示资料不足。

观察点：

- 回答是否逐字流式增长；
- 是否出现 `token`、`citation`、`done` 对应的正常结果；
- 引用文件、切片编号和距离是否展示；
- Top-K 调整为 3 时，最多召回 3 个相似切片，不是限制回答只能有 3 句话。

## 7. 故障分析

进入“故障分析”，填写：

- 故障标题：`订单服务生产环境返回 502`
- 故障日志或现象：

```text
2026-08-24 10:15:21 gateway ERROR upstream prematurely closed connection
POST /api/orders returned 502
过去五分钟订单接口 P95 延迟升高到 2.8 秒，订单服务实例没有明显重启。
```

提交后预期看到：

- 页面逐步流式显示分析结果；
- 结果结合知识库给出可能原因和排查步骤；
- 分析完成后状态被保存；
- 引用内容与订单服务故障排查手册相关。

故障分析和普通知识库问答的区别：普通问答回答一个知识问题；故障分析保存一次真实的故障输入、模型结果、状态和引用，方便以后回看、复盘和审计。

## 8. 故障历史

点击左侧“故障历史”。这个页面不是重新发起分析，而是查看过去已经提交过的故障记录：

- 标题：当时遇到的故障名称；
- 状态：completed、failed 或 cancelled；
- 创建时间：提交故障的时间；
- 查看：展开输入日志和完整分析结果；
- 删除：清理不再需要的历史记录。

预期结果：能看到刚刚提交的“订单服务生产环境返回 502”，点击查看后可以回看输入日志和分析结果。

## 9. 权限边界验证

如果条件允许，注册第二个账号：

1. 用户 A 创建知识库并上传文档；
2. 用户 B 登录后查看自己的知识库列表；
3. 手动把 URL 中的知识库数字 ID 改成用户 A 的 ID；
4. 尝试访问文档、问答和故障分析接口。

预期：用户 B 不能读取、上传、删除或问答用户 A 的知识库，后端返回未授权或无权限错误。

## 10. 删除清理验证

回到文档管理，删除一份已索引文档，再回到问答页提问该文档中的独有问题。

预期：删除后旧向量不会继续出现在引用来源中。这个验证用于确认数据库、原始文件和 Chroma 向量没有留下不可见的脏数据。

## 11. 测试完成标准

- [ ] 新用户可以注册、登录和退出；
- [ ] 协议未勾选时不能登录；
- [ ] 可以创建知识库并进入工作台；
- [ ] TXT、Markdown、PDF 都能上传并完成索引；
- [ ] 重复内容返回 duplicate，不创建无意义版本；
- [ ] 内容变化会创建新版本；
- [ ] RAG 问答能流式展示并返回引用；
- [ ] 知识库没有答案时不会凭空编造；
- [ ] 故障分析能流式生成并保存记录；
- [ ] 故障历史可以查看和删除记录；
- [ ] 不同用户之间不能越权访问；
- [ ] 删除文档后旧向量不会继续被召回。
